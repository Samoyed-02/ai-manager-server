Task 워커가 같은 작업의 문서를 두 번 저장하는 버그를 테스트로 재현하고 고쳤다.

## 커밋

| 커밋 | 메시지 |

| `fd8f251` | fix: prevent duplicate documents when a task is retried |

## 문제

`claimNext()`는 `FOR UPDATE SKIP LOCKED`로 작업을 가져오기 때문에 가져오는 단계 자체는 안전했다. 문제는 처리 결과를 저장하는 단계였다.

1. **소유권 확인 없음**: `recoverStale()`은 10분 넘게 `RUNNING`인 작업을 `PENDING`으로 되돌린다. 원래 워커가 아직 Claude 응답을 기다리는 중이어도 되돌리기 때문에, 다른 워커가 같은 작업을 다시 가져가 두 워커가 각각 문서를 저장했다. Anthropic SDK 기본 타임아웃이 약 10분이라 실제로 일어날 수 있는 상황이다.
2. **두 번에 나뉜 저장**: `documents.save`가 먼저 커밋되고 `tasks.save`가 따로 실행됐다. 그 사이에 실패하거나 서버가 죽으면 문서는 남고 작업은 `RUNNING`으로 남아, 복구 후 재실행되면서 문서가 하나 더 생겼다.
3. **예전 엔티티로 덮어쓰기**: 마지막 `tasks.save(task)`가 처리 시작 시점의 엔티티를 병합해서, 다른 워커가 올린 `attempts`와 상태를 덮어썼다.
4. **DB 제약 없음**: `documents.task_id`에 unique 제약이 없었다.

중복이 생기면 `findByTaskId`가 `IncorrectResultSizeDataAccessException`을 던져 `GET /tasks/{id}`가 500을 반환했다.

## 변경 사항

### 1. 재현 테스트 (`3ea373e`)
- `@EnableScheduling`을 `config/SchedulingConfig.kt`로 옮기고 `app.scheduling.enabled`로 끌 수 있게 함 (기본값 켜짐, 테스트에서는 끔)
  - 테스트가 `poll()`과 `recoverStale()`을 직접 호출해 순서를 제어하기 위해서
- `TaskWorkerConcurrencyTest` (Testcontainers Postgres, Claude 클라이언트는 mock)

| 테스트 | 시나리오 | 수정 전 | 수정 후 |
|---|---|---|---|
| A | 스레드 8개가 작업 20개를 동시에 `poll()` | 통과 | 통과 |
| B | 처리 중인 작업이 stale로 복구된 뒤 다른 워커가 다시 처리 | 실패 (문서 2개, 500) | 통과 |
| C | 상태 저장 직전에 실패한 뒤 복구·재시도 | 실패 (문서 2개, 500) | 통과 |

- C는 임시 Postgres 트리거로 `status = 'DONE'` update를 실패시켜 크래시를 흉내 낸다. Spring Data 리포지토리가 인터페이스 프록시라 `@MockitoSpyBean`으로는 실제 메서드를 호출할 수 없어서 이 방식을 택했다.
- Anthropic SDK가 Kotlin으로 작성돼 Mockito `any()`가 넘기는 null을 거부하므로 `anyArg()` 헬퍼를 사용한다.

### 2. 수정 (`fd8f251`)
- **소유권 토큰**: `claimNext()`가 `returning id, attempts`로 `Claim(id, attempts)`를 돌려준다. claim 시점의 `attempts`가 "이 작업이 지금 내 것"이라는 토큰이다.
- **`complete()`**: `TransactionTemplate`으로 한 트랜잭션에서 처리
  1. `update tasks set status = 'DONE' ... where id = :id and status = 'RUNNING' and attempts = :attempts`
  2. 1행이 바뀐 경우에만 `insert into documents ... on conflict (task_id) do nothing`
  3. 0행이면 다른 워커가 가져간 것이므로 결과를 버리고 경고 로그를 남긴다
- **`fail()`**: 같은 소유권 조건으로 `PENDING`/`FAILED` 전환
- **`tasks.save(task)` 제거**: 예전 엔티티 덮어쓰기 문제 해결. `TaskWorker`는 더 이상 `DocumentRepository`를 쓰지 않는다.
- **`V3__document_task_unique.sql`**
  - 기존 중복 문서는 작업마다 가장 먼저 만들어진 것만 남기고 삭제
  - `documents(task_id)`에 unique 인덱스 `uq_documents_task_id` 생성

## 배포 시 주의

- V3 마이그레이션은 운영 DB에 중복 문서가 있으면 **실제로 삭제**한다. 배포 전에 확인하려면:
  ```sql
  select task_id, count(*) from documents group by task_id having count(*) > 1;
  ```
- 소유권을 잃어 결과를 버린 경우에도 `attempts`는 올라간 값으로 남는다 (의도된 동작).

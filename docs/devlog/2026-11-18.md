# 2026-11-18 개발 기록

로그인 전체 잠금을 없앴다. IP별 잠금만 남겼다.

## 전체 로그인 잠금 제거

**문제:** 로그인 실패를 두 기준으로 막았다.
- 같은 IP에서 15분 안에 5번 실패하면 그 IP를 막는다.
- IP와 관계없이 15분 안에 실패가 50번이면 모든 로그인을 막는다.

두 번째 기준 때문에, 서버 주소를 아는 사람이 IP 10개로 5번씩 실패하면 본인도 15분 동안 새로 로그인할 수 없었다. 이미 로그인한 기기는 세션 토큰으로 계속 쓸 수 있어서, 영향은 새 기기 로그인과 만료된 세션에 한정됐다.

**결정:** 전체 기준을 지웠다.
- 로그인에는 12자 이상 비밀번호(bcrypt)와 30초마다 바뀌는 일회용 TOTP 코드가 함께 필요하다. IP 하나는 15분에 5번만 시도할 수 있다. IP를 많이 동원해도 두 값을 함께 맞힐 확률은 사실상 0이라, 전체 기준이 더하는 보안이 작았다.
- IP 위조가 통하지 않는 것은 11-07에 확인했다(`APP_TRUST_FORWARDED_FOR`). 그래서 IP별 기준은 그대로 믿을 수 있다.
- 다른 방안으로, 최근 성공한 IP는 전체 잠금에서 빼 주는 방식도 검토했다. 코드가 늘고, 휴대폰처럼 IP가 자주 바뀌면 본인도 막힐 수 있어 고르지 않았다.

**변경**
- `AuthService`: `MAX_FAILURES_TOTAL`을 지웠다. `lockedFor()`는 IP별 조회만 한다.
- `AuthApiTest`: 다른 IP 12개의 실패 60건을 넣고, 새 IP의 정상 로그인이 200인지 확인한다. 전체 잠금이 되살아나면 실패한다.
- `login_attempts(created_at)` 인덱스는 30일 지난 기록 정리에도 쓰여 그대로 뒀다.
- API 응답(429, `Retry-After`)은 그대로다.

**확인:** 테스트 175개 모두 통과(통합 129, 단위 46).

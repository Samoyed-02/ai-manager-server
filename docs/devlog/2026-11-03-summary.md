## 진행 중 알게 된 것

- **점검 문서 정정:** "연속된 user 메시지가 히스토리를 꼬이게 한다"는 처음 판단은 틀렸다. Messages API는 같은 역할의 연속 메시지를 하나로 합쳐 처리한다. 실제 문제는 부분 응답이 사라지는 것이었다.
- **커밋 기록 정정:** Task 모듈은 초기 커밋이 아니라 `8155eb3 fix: chatService prompt fix`에서 추가됐다.
- **로컬 개발 DB:** `bootRun`으로 확인하면서 V3·V4가 로컬 개발 DB에 적용됐다. V3 적용 전에 중복 문서가 있었는지는 알 수 없다(현재 작업 1개, 문서 1개). V5는 아직 로컬에 적용되지 않았다.
- **테스트 작성 중 겪은 문제:** Kotlin으로 작성된 Anthropic SDK가 Mockito `any()`의 null을 거부해 `anyArg()` 헬퍼를 만들었다. Spring Data 리포지토리는 인터페이스 프록시라 `@MockitoSpyBean`이 실제 메서드를 호출하지 못해서, DB 트리거로 크래시를 흉내 냈다. MockMvc 응답은 기본 ISO-8859-1이라 UTF-8로 읽어야 했다.
- **운영 설정:** `application.yml`에 `spring.datasource`가 없다. 개발에서는 `spring-boot-docker-compose`가 넣어 주지만 jar에는 들어가지 않아, 운영에서는 `SPRING_DATASOURCE_*`를 꼭 넣어야 한다. 실제 이미지를 띄워 확인했다.
- **CI:** Private 저장소라 무료 플랜에서 "CI 통과해야 병합" 규칙을 걸 수 없다. 병합 전에 `gh pr checks --watch`로 확인하는 절차로 대신한다. Gradle 기본 로그에는 테스트 개수가 나오지 않는다.
- **구조화 로그:** Spring Boot의 ECS JSON 로그는 SLF4J key-value를 필드로 넣는다. 값을 문자열로 넘기면 숫자도 `"849"`처럼 문자열이 되어, 숫자는 그대로 넘기게 고쳤다.
- **삭제와 진행 중 작업:** 처리 중인 작업은 워커의 소유권 확인(조건부 update) 덕분에 지우기만 해도 취소처럼 동작했다. 반면 답변 스트리밍 중 대화를 지우면 저장 시 외래 키 오류로 클라이언트가 아무 이벤트도 받지 못해, 대화 행을 잠그고 저장하게 고쳤다.
- **웹 도구 문서 확인:** 웹 검색은 조직 설정에서 기본으로 켜져 있지만 관리자가 끄면 요청 전체가 400이 된다. 검색 결과를 보여줄 때는 출처를 함께 표시해야 한다. 페이지 읽기는 대화에 이미 나온 URL만 읽을 수 있고, 인용에 URL이 없다.
- **Sonnet 5.5와 도구:** `tool_choice`로 도구를 강제하면 400이 나서 프롬프트로만 안내한다. 도구 호출 사이 문구가 `thinking` 블록으로 올 수 있어, 이어 보낼 때 받은 응답을 바꾸지 않고 통째로 붙인다.
- **테스트 fixture:** SDK `MessageAccumulator`는 이벤트를 `accept()`로 읽어 Mockito mock으로는 응답을 조립할 수 없었다. SDK의 JSON 매퍼(`com.anthropic.core.jsonMapper`)로 실제 API 모양의 이벤트를 만드는 `ChatStreamScript`를 만들었다. 기존 mock 테스트는 그대로 두었고, 모으기 실패는 이어 받기만 포기하도록 해서 함께 돈다.

- **배포:** [배포 체크리스트](../deploy-checklist.md)를 따른다. 플랫폼이 HTTP 헬스체크를 요구하면 헬스체크 경로를 추가한다.
- **첫 실제 호출 확인:** 사용량 로그의 토큰 수와 웹 검색은 mock으로만 확인했다. 실제 키로 채팅·작업을 한 번씩 돌려 `claude.usage` 로그를 보고, 최신 정보 질문으로 출처 목록이 붙는지 본다.
- **도구 다음 단계:** 지난 문서·대화 검색 같은 다른 도구, 문서 작성 작업에 웹 검색 붙이기(작업 타임아웃 조정 필요). `create_task`가 실제로 언제 불리는지는 `tool_calls` 로그로 보고 설명을 다듬는다.
- **운영 DB:** 정할 때 Postgres 17이 아니면 `compose.yaml`과 `TestcontainersConfiguration`을 함께 바꾼다.
- **배포:** 운영 DB에 중복 문서가 있으면 V3가 삭제하므로, 배포 전에 확인한다.
  ```sql
  select task_id, count(*) from documents group by task_id having count(*) > 1;
  ```
- **프론트엔드**
  - 채팅 `error` 이벤트를 받으면 입력 내용을 지우지 않고 남겨 두기
  - 메시지 `status`(잘림, 중단됨 등) 표시
  - 400 응답의 `fields`를 입력란 옆에 표시
  - 삭제 버튼과 확인 창 (영구 삭제), `CONVERSATION_DELETED` 처리, `DONE`인데 `documentId`가 `null`이면 "문서 삭제됨" 표시
  - 채팅 `task` 이벤트를 받으면 작업 카드(진행 상태, 완료 시 문서 링크) 표시
- **나중에 검토할 것:** 모두 `claude.usage` 로그를 보고 정한다. 볼 값은 [2026-11-03.md](2026-11-03.md#claude-사용량-로그)에 정리했다.
  - Task `maxTokens(8192)` 상향과 streaming 전환 (`stop_reason=max_tokens` 비율, `output_tokens` 분포)

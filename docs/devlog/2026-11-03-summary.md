## 바뀐 동작 (API·운영)

새 필드나 새 형식이 추가된 것이라 기존 클라이언트가 깨지지는 않는다.

| 대상 | 변경 |
|---|---|
| `POST /chat` `done` 이벤트 | `{}` → `{"status": "COMPLETE" \| "TRUNCATED" \| "REFUSED"}` |
| `POST /chat` `error` 이벤트 | 예외 원문 → `{"code": "...", "message": "안내 문구"}` |
| `POST /chat` 실패 처리 | 텍스트가 오기 전에 실패하면 사용자 메시지 삭제 (새 대화였다면 대화도 삭제) |
| `GET /conversations/{id}/messages` | `status` 필드 추가 |
| `GET /tasks`, `GET /tasks/{id}` | `error`에 원문 대신 안내 문구 |
| 모든 요청 본문 | 길이 제한, 실패 시 `400 {"error": "invalid_request", "fields": {...}}` |
| `POST /tasks` | `type`은 `document`만 허용 |
| 작업 실패 | 잘림·거절·401·400 등은 재시도 없이 바로 `FAILED` |
| 서버 포트 | `PORT` 환경변수 사용 (없으면 8080) |
| Docker 컨테이너 | `app`(uid 10001) 사용자로 실행 |
| `APP_PASSCODE` | 비어 있거나 공백뿐이면 서버가 뜨지 않음 |
| `DELETE /conversations/{id}`, `/tasks/{id}`, `/documents/{id}` | 새 API. 성공 204, 없으면 404. 작업을 지워도 문서는 남음 |
| `POST /chat` `error` 이벤트 | 답변 도중 대화가 삭제되면 `CONVERSATION_DELETED` |
| `POST /chat` 답변 | 필요하면 웹을 검색·읽고, 그때는 답변 끝에 `**출처**` 링크 목록이 붙음 (저장되는 내용에도 포함) |
| `POST /chat` `task` 이벤트 | 새 이벤트. 채팅에서 문서 작성 작업을 만들면 `{"taskId", "instruction"}` |
| `POST /voice/calls` | 새 API. 통화 기록을 `VOICE` 대화로 저장 |
| `GET/POST /memories`, `PUT/DELETE /memories/{id}` | 새 API. AI가 기억하는 내용 조회·수정. 민감 정보는 400 |
| `GET /conversations` | `channel`(`CHAT`/`VOICE`) 필드 추가 |
| 채팅·통화 맥락 | 기억과 최근 대화 요약이 들어감. 대화가 끝나면 Claude 호출이 한 번 더 생김(`kind=memory`) |
| `POST /chat` `action` 이벤트 | 새 이벤트. 기억·루틴·활동 도구를 실행하면 `{"tool", "summary"}` |
| `GET /tools`, `POST /tools/{name}` | 새 API. 통화(Gemini)용 도구 목록과 실행 |
| `/routines`, `/notifications`, `/activities` | 새 API. 루틴 관리, 알림함, 활동 기록 |
| 채팅·통화 맥락 (2단계) | 읽지 않은 알림, 켜진 루틴, 최근 7일 활동이 들어감. 브리핑 루틴은 실행마다 Claude 호출(`kind=routine`) |
| `/goals`, `/reviews` | 새 API. 목표(이번 주 진행 포함), 주간 회고 |
| 채팅·통화 맥락 (3단계) | 진행 중인 목표와 이번 주 진행, 최근 회고가 들어감 |
| 주간 회고 | 기본 루틴이 매주 일요일 21:00에 실행(`kind=review`, 주 1회 Claude 호출) |
| **인증** | `POST /auth/login`(비밀번호 + 6자리 코드) → 토큰. 모든 요청에 `Authorization: Bearer <token>`. `X-App-Passcode`는 `APP_PASSCODE`가 있을 때만 전환용으로 받음 |
| `/auth/logout`, `/auth/sessions` | 새 API. 로그아웃, 기기 목록, 기기 끊기 |
| 필수 환경변수 | `APP_PASSWORD_HASH`, `APP_TOTP_SECRET` 추가. `APP_PASSCODE`는 선택(전환용) |
| 모든 응답 | `Cache-Control: no-store`, `nosniff`, `no-referrer` (HTTPS면 HSTS) |
| 로그 | Claude 호출마다 `claude.usage` 로그 한 줄. `LOGGING_STRUCTURED_FORMAT_CONSOLE=ecs`면 JSON |

## 진행 중 알게 된 것

- **점검 문서 정정:** "연속된 user 메시지가 히스토리를 꼬이게 한다"는 처음 판단은 틀렸다. Messages API는 같은 역할의 연속 메시지를 하나로 합쳐 처리한다. 실제 문제는 부분 응답이 사라지는 것이었다.
- **커밋 기록 정정:** Task 모듈은 초기 커밋이 아니라 `8155eb3 fix: chatService prompt fix`에서 추가됐다.
- **로컬 개발 DB:** `bootRun`으로 확인하면서 V3·V4가 로컬 개발 DB에 적용됐다. V3 적용 전에 중복 문서가 있었는지는 알 수 없다(현재 작업 1개, 문서 1개). V5는 아직 로컬에 적용되지 않았다.
- **테스트 작성 중 겪은 문제:** Kotlin으로 작성된 Anthropic SDK가 Mockito `any()`의 null을 거부해 `anyArg()` 헬퍼를 만들었다. Spring Data 리포지토리는 인터페이스 프록시라 `@MockitoSpyBean`이 실제 메서드를 호출하지 못해서, DB 트리거로 크래시를 흉내 냈다. MockMvc 응답은 기본 ISO-8859-1이라 UTF-8로 읽어야 했다.
- **운영 설정:** `application.yml`에 `spring.datasource`가 없다. 개발에서는 `spring-boot-docker-compose`가 넣어 주지만 jar에는 들어가지 않아, 운영에서는 `SPRING_DATASOURCE_*`를 꼭 넣어야 한다. 실제 이미지를 띄워 확인했다.
- **CI:** Private 저장소라 무료 플랜에서 "CI 통과해야 병합" 규칙을 걸 수 없다. 병합 전에 `gh pr checks --watch`로 확인하는 절차로 대신한다. Gradle 기본 로그에는 테스트 개수가 나오지 않는다.
- **구조화 로그:** Spring Boot의 ECS JSON 로그는 SLF4J key-value를 필드로 넣는다. 값을 문자열로 넘기면 숫자도 `"849"`처럼 문자열이 되어, 숫자는 그대로 넘기게 고쳤다.
- **삭제와 진행 중 작업:** 처리 중인 작업은 워커의 소유권 확인(조건부 update) 덕분에 지우기만 해도 취소처럼 동작했다. 반면 답변 스트리밍 중 대화를 지우면 저장 시 외래 키 오류로 클라이언트가 아무 이벤트도 받지 못해, 대화 행을 잠그고 저장하게 고쳤다.
- **웹 도구 문서 확인:** 웹 검색은 조직 설정에서 기본으로 켜져 있지만 관리자가 끄면 요청 전체가 400이 된다. 검색 결과를 보여줄 때는 출처를 함께 표시해야 한다. 페이지 읽기는 대화에 이미 나온 URL만 읽을 수 있고, 인용에 URL이 없다.
- **Sonnet 5.5와 도구:** `tool_choice`로 도구를 강제하면 400이 나서 프롬프트로만 안내한다. 도구 호출 사이 문구가 `thinking` 블록으로 올 수 있어, 이어 보낼 때 받은 응답을 바꾸지 않고 통째로 붙인다.
- **통화는 서버를 거치지 않았다:** 통화(Gemini)는 클라이언트가 직접 연결하고 서버는 시작할 때 고정된 맥락만 줘서, 통화를 끊으면 내용이 사라지고 통화·채팅이 서로 몰랐다. 기억·도구를 서버에 두고 클라이언트가 기록을 보내고(`/voice/calls`) 도구 호출을 중계하는(`/tools`) 구조로 바꿨다. 클라이언트 작업이 있어야 통화 쪽이 동작한다.
- **숫자는 서버가:** 목표 진행과 회고 통계는 서버가 계산하고 Claude는 해석만 쓰게 했다. 모델이 합계를 틀리게 말하지 않게 하려는 것이다.
- **JPA 엔티티와 워커 컬럼:** 워커가 JDBC로 쓰는 `conversations.summary`를 엔티티에서 쓰기 가능하게 두면, 미리 읽어 둔 엔티티를 저장할 때 덮어쓴다. 읽기 전용으로 매핑하고 워커 전용 컬럼은 엔티티에 넣지 않았다.
- **테스트 중 발견:** JdbcClient `single()`은 null 행을 거부한다(`list().single()`로). MockMvc `jsonPath`는 리스트 전체를 `value(List)`로 비교하면 `null`로 나와 원소별로 비교했다. 한 번은 Testcontainers Postgres 연결 실패로 `contextLoads`가 실패했는데 다시 돌리면 통과했다.
- **테스트 fixture:** SDK `MessageAccumulator`는 이벤트를 `accept()`로 읽어 Mockito mock으로는 응답을 조립할 수 없었다. SDK의 JSON 매퍼(`com.anthropic.core.jsonMapper`)로 실제 API 모양의 이벤트를 만드는 `ChatStreamScript`를 만들었다. 기존 mock 테스트는 그대로 두었고, 모으기 실패는 이어 받기만 포기하도록 해서 함께 돈다.

## 남은 일

서버 쪽 1~3단계는 끝났다. 남은 것은 실제 API 키로 한 바퀴 점검, 인증 강화, 배포, 푸시 알림(3-2단계), 프론트엔드 반영이다.

- **실제 API 점검:** 기억 추출·도구 선택·브리핑·회고 품질과 사용량 로그는 mock으로만 확인했다.
- **인증 전환 마무리:** 서버는 로그인·세션으로 바뀌었다(#26). 프론트엔드가 로그인 화면과 `Authorization: Bearer`로 바뀌면 `APP_PASSCODE`를 지운다.

- **배포:** [배포 체크리스트](../deploy-checklist.md)를 따른다. 플랫폼이 HTTP 헬스체크를 요구하면 헬스체크 경로를 추가한다.
- **첫 실제 호출 확인:** 사용량 로그의 토큰 수와 웹 검색은 mock으로만 확인했다. 실제 키로 채팅·작업을 한 번씩 돌려 `claude.usage` 로그를 보고, 최신 정보 질문으로 출처 목록이 붙는지 본다.
- **도구 다음 단계:** 지난 문서·대화 검색 같은 다른 도구, 문서 작성 작업에 웹 검색 붙이기(작업 타임아웃 조정 필요). `create_task`가 실제로 언제 불리는지는 `tool_calls` 로그로 보고 설명을 다듬는다.
- **운영 DB:** 정할 때 Postgres 17이 아니면 `compose.yaml`과 `TestcontainersConfiguration`을 함께 바꾼다.
- **배포:** 운영 DB에 중복 문서가 있으면 V3가 삭제하므로, 배포 전에 확인한다.
  ```sql
  select task_id, count(*) from documents group by task_id having count(*) > 1;
  ```
- **프론트엔드**
  - 채팅 `error` 이벤트를 받으면 입력 내용을 지우지 않고 남겨 두기
  - 메시지 `status`(잘림, 중단됨 등) 표시
  - 400 응답의 `fields`를 입력란 옆에 표시
  - 삭제 버튼과 확인 창 (영구 삭제), `CONVERSATION_DELETED` 처리, `DONE`인데 `documentId`가 `null`이면 "문서 삭제됨" 표시
  - 채팅 `task` 이벤트를 받으면 작업 카드(진행 상태, 완료 시 문서 링크) 표시
  - **로그인 화면(비밀번호 + 인증 앱 6자리 코드, 기기 이름), 토큰 저장, 모든 요청에 `Authorization: Bearer`, 401이면 로그인, 기기 목록·끊기 화면** (바꾼 뒤 `APP_PASSCODE` 삭제)
  - **통화가 끝나면 받아 적은 기록으로 `POST /voice/calls` 호출** (이게 있어야 통화 기억이 쌓임)
  - 기억 관리 화면(`/memories`), 대화 목록에 통화·채팅 구분 표시
  - **통화: `GET /tools`를 Gemini 함수 선언으로 등록하고, 함수 호출을 `POST /tools/{name}`으로 중계해 결과를 돌려주기** (이게 있어야 통화 중 도구가 동작)
  - 채팅 `action` 이벤트 표시, 알림함·루틴 관리·활동 기록 화면
  - 목표 화면(이번 주 진행 막대, D-day), 주간 회고 화면
- **푸시 알림 (3-2단계):** 클라이언트가 웹(PWA, Web Push)인지 앱(FCM/APNs)인지 확인한 뒤 진행한다. 그 전까지 브리핑·회고는 알림함과 다음 대화로 전달된다.
- **나중에 검토할 것:** 모두 `claude.usage` 로그를 보고 정한다. 볼 값은 [2026-11-03.md](2026-11-03.md#claude-사용량-로그)에 정리했다.
  - Task `maxTokens(8192)` 상향과 streaming 전환 (`stop_reason=max_tokens` 비율, `output_tokens` 분포)
  - 거절 시 다른 모델로 재요청하는 server-side `fallbacks`(beta) (`stop_reason=refusal` 비율)
  - 채팅 히스토리를 메시지 개수가 아니라 토큰 기준으로 자르기 (`kind=chat`의 `input_tokens`)
  - 로그 보관 기간이 짧으면 사용량을 DB(`claude_calls`)에도 저장

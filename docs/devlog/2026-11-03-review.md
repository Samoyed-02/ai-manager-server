## 상세

### 1. Task 응답의 `stop_reason` 미확인 (높음) — ✅ 완료
- 처리: PR #5 (`f279d8b`). 잘림·거절·예상 밖 종료는 재시도 없이 `FAILED`, 빈 본문은 재시도. 자세한 내용은 [2026-11-03.md](2026-11-03.md)의 "잘리거나 거절된 Claude 응답 처리".

- 위치: `TaskWorker.runClaude()`
- 현재: 응답의 텍스트 블록을 이어 붙여 그대로 문서로 저장한다.
- 문제
  - `stop_reason == "max_tokens"`: 8192 토큰에서 잘린 문서가 `DONE`으로 저장된다. `claude-sonnet-5-5`는 thinking이 기본으로 켜져 있고 thinking도 `max_tokens` 안에서 쓰기 때문에, 긴 문서에서 잘릴 가능성이 있다.
  - `stop_reason == "refusal"`: 거절 응답(빈 텍스트나 짧은 안내)이 문서로 저장된다.
- 제안: `end_turn`이 아니면 예외를 던져 기존 재시도·실패 경로를 타게 한다. `max_tokens`는 한도를 늘리거나 streaming으로 바꾸는 것도 검토한다.

### 2. 채팅 실패 시 히스토리 불일치 (높음) — ✅ 완료
- 처리: PR #6 (`cf303c9`). 자세한 내용은 [2026-11-03.md](2026-11-03.md)의 "채팅 실패 시 기록 정리".
- 위치: `ChatController.chat()`, `ChatService.prepare()`
- 현재: 사용자 메시지를 먼저 저장하고, assistant 응답은 스트리밍이 끝난 뒤에만 저장한다.
- 문제: Claude 오류, `SseEmitter` 타임아웃(180초), 브라우저 연결 끊김이 생기면 사용자 메시지만 남는다. 사용자가 화면에서 본 부분 응답은 새로고침하면 사라지고, 다음 요청에서 Claude는 같은 질문을 두 번 받은 것처럼 보게 된다.
  - 정정: 처음에는 "user 메시지가 연속으로 들어가 히스토리가 꼬인다"고 적었지만, Messages API는 연속된 같은 역할 메시지를 하나로 합쳐 처리하므로 API 오류가 나지는 않는다.
- 제안: 실패하면 부분 응답을 `[중단됨]` 표시와 함께 저장하거나, 사용자 메시지를 롤백한다. 채팅도 `stop_reason`을 확인한다.

### 3. 제목만 필요한데 본문까지 조회 (중간) — ✅ 완료
- 처리: PR #8 (`d3c12fd`). 자세한 내용은 [2026-11-03.md](2026-11-03.md)의 "문서 조회 최적화".
- 위치: `ContextService.recentDocTitles()`, `TaskController.documents()`
- 현재: `findTop50ByOrderByCreatedAtDesc()`로 `content`(text)까지 포함한 문서 50개를 읽은 뒤 제목 5~10개만 쓴다. `forClaude()`는 채팅과 작업마다 호출된다.
- 제안: 제목만 읽는 projection 쿼리(`select id, task_id, title, created_at ... limit :n`)를 쓰고, `documents(created_at)` 인덱스를 추가한다.

### 4. `GET /tasks`의 N+1 조회 (중간) — ✅ 완료
- 처리: PR #8 (`d3c12fd`). 문서 ID를 `findByTaskIdIn`으로 한 번에 조회해 SQL 문이 2개로 줄었다.
- 위치: `TaskController.toDto()`
- 현재: `DONE` 작업마다 `findByTaskId`를 호출해, 최대 20번 추가로 조회한다. 이때 문서 본문도 함께 읽는다.
- 제안: 작업 ID 목록으로 문서 ID를 한 번에 조회(`where task_id in (...)`)하거나, 조인 쿼리로 바꾼다.

### 5. 테스트 범위 (중간) — ✅ 완료
- 점검 당시 테스트는 `contextLoads`와 `TaskWorkerConcurrencyTest`뿐이었다.
- 추가됨: `TaskWorkerStopReasonTest`(#5), `ChatServiceTest`(#6, 채팅 응답 흐름과 이벤트 순서·실패 처리), `ClaudeErrorsTest`(#7), `TaskControllerTest`(#8, 작업·문서 목록과 SQL 문 수)
- 추가됨 (#9): 점검 때 적은 후보 4개

- 테스트 수: 점검 당시 4개 → 32개

### 9. 재시도할 수 없는 오류도 재시도 (낮음) — ✅ 완료

- 처리됨 (#7): SDK 예외를 `classifyClaudeError()`로 분류해, `CONFIG`(401·403·404)와 `BAD_REQUEST`(400·413·422)도 재시도 없이 실패시킨다. 예외 클래스는 `TaskFailureException(message, retryable)`로 일반화했다.

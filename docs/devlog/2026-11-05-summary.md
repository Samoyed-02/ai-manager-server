## 바뀐 동작 (API·운영)

- `GET /conversations/{id}/messages`의 각 메시지에 `actions: [...]`가 추가됐다. 그 답변에서 서버가 실행한 작업이다.
- 채팅 답변 끝의 목록이 두 가지가 됐다.
  - 인용이 있으면 **출처**
  - 인용이 없으면 답변과 겹치는 **검색한 페이지**
- 도구를 사이에 둔 답변 텍스트는 빈 줄로 나뉘어 스트리밍된다.
- 서버 도구 바로 앞의 짧은 진행 문장은 스트리밍되지도, 저장되지도 않는다.
- 설정 `claude.context-as-system-message`(기본 `true`): `false`면 맥락을 시스템 프롬프트에 넣는 예전 방식으로 돌아간다.
- 로그
  - `claude.usage`에 `cache_read_tokens`와 `cache_creation_tokens`가 실제 값으로 찍힌다.
  - `chat.blocks`(debug)에 응답 블록 구성과 텍스트 버림 여부가 찍힌다.
- 질문당 웹 검색은 최대 6회다(검색비 최대 $0.06).
- `GET /actuator/health`가 인증 없이 열린다. 상태만 돌려주고, DB에 연결하지 못하면 503이다.
- `railway.json`이 Railway 화면 설정보다 우선한다. 헬스체크에 실패한 새 배포는 트래픽을 받지 않는다.

## 진행 중 알게 된 것

- 동적 필터링 웹 검색(`web_search_20260209`)의 답변에는 인용이 거의 달리지 않는다. 결과를 코드로 걸러 쓰기 때문이다.
- SDK `MessageAccumulator`는 입력 조각 없이 온 도구 블록에서 실패한다. 최신 SDK(3.4.0)에서도 고쳐졌다는 기록은 찾지 못했다.
- Kotlin에서 `List<@Valid T>`는 `-Xemit-jvm-type-annotations` 없이는 아무 효과가 없다. 경고만 사라지므로 알아채기 어렵다.
- `src/test/resources/application.yml`은 운영 `application.yml`을 통째로 가린다. 테스트와 공유할 설정은 `management.yml`처럼 따로 빼서 가져온다.
- `gh pr checks --watch`는 CI가 등록되기 전에 부르면 바로 끝난다. 그래서 #33은 CI 전에 병합됐다(병합 뒤 `main` CI는 통과).

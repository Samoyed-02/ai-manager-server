## 프론트엔드 (별도 저장소)

- 로그인과 Bearer 인증

- 음성 도구 연결 (`GET /tools`, `POST /tools/{name}`)

- 밝은 톤 디자인, 새 아이콘
- 기기에서 듣고 있다가 "수피"를 부르면 통화를 시작하는 방식

프론트엔드에 넘길 서버 정보는 11-07에 정리했다. 인증, 채팅 SSE 이벤트, 통화, 도구 중계 계약과 우선순위가 들어 있다.

- `.gitignore`에 `.env`, `.env.*`, `*.env`를 추가했다.
- `scripts/live-check.sh`의 임시 DB를 `postgres:18`로 바꿨다. 문법만 확인했고, 실제 실행은 API 비용이 들어 하지 않았다.

## 예전 패스코드 인증 제거 (#47)와 후속 수정

다른 세션에서 만든 #47이 14:21에 병합됐다. 예전 `X-App-Passcode` 인증과 `APP_PASSCODE` 설정을 지우고 README를 추가한 PR이다. 이 세션에서 검토한 뒤 지적한 것을 후속 PR로 고쳤다.

- 세션 관리 API 네 개(`logout`, `sessions`, `revoke`, `revokeOthers`)가 모두 `currentSession()`을 쓴다. 예전에는 `sessions`와 `revoke`만 패스코드 요청 때문에 세션 없이도 진행했다. 이제 넷 다 세션이 없으면 403이다. Bearer 요청에는 항상 세션이 있으므로 API 계약은 그대로다.
- "예전 헤더를 받지 않는다" 테스트가 헤더 없는 401 테스트와 같았다. `app.passcode`를 설정한 별도 클래스로 옮겨서, 패스코드 지원이 되살아나면 실패하게 했다.
- 위 403 경로는 HTTP로는 필터가 먼저 401을 줘서 닿지 않는다. 그래서 컨트롤러를 직접 불러 확인하는 테스트를 추가했다.
- `scripts/live-check.sh`에서 사라진 경고를 거르던 `grep -v 'APP_PASSCODE'`를 지웠다.
- 테스트는 174개 모두 통과했다. #47에서 패스코드 테스트가 빠지면서 175개에서 줄었다.

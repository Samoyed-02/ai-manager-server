# 실제 Claude API 점검 (2026-11-04)

`scripts/live-check.sh`로 실제 Docker 이미지 + 임시 Postgres 17 + 새 테스트 자격 증명을 띄우고, 실제 Claude API(`claude-sonnet-5-5`)로 17개 시나리오를 한 번씩 돌렸다. 컨테이너는 끝난 뒤 모두 지웠다.

```
scripts/live-check.sh ~/.ai-manager-live.env 2    # env 파일에 ANTHROPIC_API_KEY, 예산 $2
```

- 호출 16회, 추정 비용 **$0.60** (정가 기준: 입력 $2 / 출력 $10 per MTok, 웹 검색 $0.01/회). 예산 $2 안.
- 401·400 같은 막히는 오류는 없었다.

## 발견한 문제

### 1. 웹 검색 답변에 출처가 붙지 않는다 (중요)

- 검색은 했다(`web_search_requests=1`). 하지만 출처 목록은 스트림의 `web_search_result_location` 인용에서만 모으는데, 이번 답변에는 인용이 없어 출처 목록이 비었다.
- 같은 호출에서 `MessageAccumulator`가 실패했다: `AnthropicInvalidDataException: Missing input JSON for index 1`. `web_search_20260209`(동적 필터링)의 서버 도구 블록이 입력 델타 없이 오는 것으로 보인다. 이 상태에서 `pause_turn`이 오면 이어 받기를 못 한다.
- 모델은 출처가 붙는다고 믿고 "링크는 답변 끝에 붙습니다"라고 썼다.
- 방향: 검색 결과 블록(`web_search_tool_result`)에서도 출처를 모으고, 누적 실패 원인(입력 없는 서버 도구 블록)을 확인한다.
- **수정됨:** 입력 조각 없이 끝난 도구 블록에는 시작 때 받은 입력을 조각으로 넣어 모은다. 인용이 없으면 검색 결과 상위 5개를 "검색한 페이지"로 붙인다. 아래 "재점검" 참고.

### 2. 대화 기록에 도구 실행 흔적이 없어 모델이 자기 행동을 부정한다 (중요)

- 대화 기록에는 답변 텍스트만 저장된다. 다음 턴의 모델은 "목표를 등록했어요"라는 말만 보고, 그 근거(도구 호출·결과)는 보지 못한다.
- 그래서 4번에서는 검색해서 답한 날씨를 "검색 결과가 아니었으니 믿지 마세요"라고 했다. 9번에서는 실제로 등록한 목표·활동·루틴을 "도구를 호출한 결과가 아니었다"고 정정했다. 데이터는 실제로 다 저장돼 있었다.
- 사용자에게 잘못된 정정을 해서 신뢰를 깎는다.
- 방향: 저장하는 어시스턴트 메시지에 실행한 작업 요약(`action` 이벤트의 summary, 사용한 출처)을 함께 남겨 다음 턴 기록에 넣는다.
- **수정됨:** `messages.actions`(V10)에 실행한 작업을 저장하고, 다음 요청에서 답변 앞에 `[서버 기록]`으로 붙인다. `GET /conversations/{id}/messages`도 `actions`를 내려 준다.

### 3. 프롬프트 캐시를 쓰지 않는다 (비용)

- 모든 호출이 `cache_read_tokens=0`이다. 채팅 요청 한 번의 입력이 약 1.1~1.3만 토큰이다. 도구를 쓴 턴은 요청이 2번이라 약 2.5만 토큰이다.
- 시스템 프롬프트·도구 정의 대부분이 매번 같으므로 캐시를 쓰면 이 부분은 정가의 10%만 낸다. 채팅이 전체 비용의 89%($0.54/$0.60)다.
- 방향: 변하지 않는 앞부분(도구, 고정 지시)에 캐시 지점을 두고, 매번 바뀌는 맥락(시각, 알림, 활동)은 뒤로 보낸다.
- **수정됨:** 고정 지시와 현재 사용자 메시지에 캐시 지점을 둔다. 맥락은 대화 기록 뒤의 system 메시지로 보낸다. 같은 턴의 도구 라운드는 자동 캐시 지점으로 처리한다. 아래 "재점검: 프롬프트 캐시" 참고.

### 4. 작은 것

- 통화에서 말한 "하체 운동 1시간"은 기억에는 들어갔지만 활동 기록에는 없다. 통화 중 도구를 쓰지 않았으니 설계대로다. 다음 채팅에서 모델이 "기록에 추가할까요?"라고 먼저 물었다.
- 기동 시 경고: `HV000271: Using @Valid on a container (java.util.List) is deprecated` (`VoiceCallRequest.turns`). `List<@Valid VoiceTurn>`로 바꾸면 된다.

## 재점검: 웹 검색 출처 (같은 날, `ONLY=3,17`)

2번 수정 뒤 웹 검색 질문 2개만 다시 돌렸다. 두 번 돌렸고, 한 번에 약 $0.10이 들었다.

- 누적 실패 경고는 사라졌다.
- 두 답변 모두 인용이 0개였고, 대신 **검색한 페이지** 5개가 붙었다. 기상청 날씨누리와 날씨 기사들이었다.
- `chat.blocks` 진단 로그로 본 실제 응답 형태:
  ```
  [thinking, server_tool_use:code_execution, server_tool_use:web_search, web_search_tool_result:9,
   code_execution_tool_result:encrypted, server_tool_use:code_execution, code_execution_tool_result:rc=0, ..., thinking, text]
  ```
  모델은 동적 필터링 코드(`code_execution`) 안에서 `web_search`를 부르고, 결과를 코드로 걸러서 쓴다. 답변에 인용이 달리지 않는 것은 이 때문이다.

### 새로 발견: 검색 한도 3회가 동적 필터링에는 빠듯하다

- "이번 주 국내 IT 업계 주요 뉴스 3개만 알려줘"를 두 번 다 실패했다. 모델은 "검색 호출이 한도를 넘었다"며 뉴스를 꼽지 않았다.
- 로그를 보면 코드 한 번 안에서 검색을 3번 연달아 불러 `max_uses=3`(`MAX_WEB_SEARCHES`)을 모두 썼다. 이후 단계는 결과를 받지 못했다.
- 정직하게 "확인하지 못했다"고 답한 것은 좋다. 하지만 뉴스 요약처럼 흔한 요청이 실패한다.
- 방향: 한도를 5~6회로 올릴지 정한다. 검색 1회는 $0.01이다. 출처 질문에 "출처는 서버가 처리한다"고 설명하는 군더더기 문장도 프롬프트로 줄일 수 있다.

- **수정됨:** 검색 한도를 6회로 올렸다. 프롬프트에 "한도에 걸리면 이미 찾은 결과로 답하라"는 지시를 넣고, 출처 지시 문장에서 "서버가 처리한다"는 이유를 뺐다.

### 재점검: 검색한 페이지 고르기 (11월 5일, `ONLY=3` 두 번)

### 새로 발견: 내부 문장이 답변에 섞인다

- 2차 뉴스 답변이 "Results are a JSON string; parse it."로 시작했다. 동적 필터링 코드를 쓰기 전에 모델이 낸 텍스트가 그대로 스트리밍됐다.
- **수정:** 서버 도구 바로 앞에 혼자 나온 짧은 텍스트를 보내지 않는다(`InterimTextFilter.kt`). 프롬프트에도 "웹 검색이나 코드 실행 전에는 글을 쓰지 말고, 결과를 다 본 뒤 한 번에 답해"를 넣었다.
  - 대상: 응답 시작이나 도구 바로 뒤에 혼자 나온 텍스트 블록
  - 앞의 150자를 모아 두었다가, 그 안에서 블록이 끝나고 서버 도구(웹 검색, 코드 실행, 페이지 읽기)가 시작되면 버린다.
  - 버리지 않는 경우: 텍스트에 바로 이어진 블록, 인용이 달린 텍스트, 우리 서버 도구 앞의 문장
  - 도구를 사이에 둔 텍스트는 빈 줄로 나눈다.
  - 진단 로그의 텍스트 블록에 길이와 버림 여부를 남긴다. 예: `text:37:dropped`

### 재점검: 내부 문장 (11월 5일, `ONLY=3,17`, $0.073)

- 두 답변 모두 정상이었다. 다만 이번에는 도구 앞에 텍스트를 낸 응답이 없어(`dropped` 0건), 원인 추정과 수정 효과를 실제 응답으로는 확인하지 못했다. 테스트로만 확인했다.
- 블록 로그로 본 실제 응답 형태:
  ```
  날씨: [server_tool_use:code_execution, ..., thinking, text:437]
  뉴스: [server_tool_use:code_execution, ..., thinking, server_tool_use:code_execution, code_execution_tool_result:rc=0,
         text:71, text:58, text:6, text:76, text:116, ...(텍스트 블록 13개)]
  ```
  최종 답변도 짧은 텍스트 블록 여러 개로 온다. 첫 블록만 잠깐 모아 두고 나머지는 바로 보내므로 버려지지 않는다.

- 이번 주 뉴스 질문은 검색 1회로 끝났다.

# 실제 Claude API 점검 (2026-11-04)

`scripts/live-check.sh`로 실제 Docker 이미지 + 임시 Postgres 17 + 새 테스트 자격 증명을 띄우고, 실제 Claude API(`claude-sonnet-5-5`)로 17개 시나리오를 한 번씩 돌렸다. 컨테이너는 끝난 뒤 모두 지웠다.

```
scripts/live-check.sh ~/.ai-manager-live.env 2    # env 파일에 ANTHROPIC_API_KEY, 예산 $2
```

- 호출 16회, 추정 비용 **$0.60** (정가 기준: 입력 $2 / 출력 $10 per MTok, 웹 검색 $0.01/회). 예산 $2 안.
- 401·400 같은 막히는 오류는 없었다.

## 발견한 문제

### 1. 웹 검색 답변에 출처가 붙지 않는다 (중요)

- 검색은 했다(`web_search_requests=1`). 하지만 출처 목록은 스트림의 `web_search_result_location` 인용에서만 모으는데, 이번 답변에는 인용이 없어 출처 목록이 비었다.
- 같은 호출에서 `MessageAccumulator`가 실패했다: `AnthropicInvalidDataException: Missing input JSON for index 1`. `web_search_20260209`(동적 필터링)의 서버 도구 블록이 입력 델타 없이 오는 것으로 보인다. 이 상태에서 `pause_turn`이 오면 이어 받기를 못 한다.
- 모델은 출처가 붙는다고 믿고 "링크는 답변 끝에 붙습니다"라고 썼다.
- 방향: 검색 결과 블록(`web_search_tool_result`)에서도 출처를 모으고, 누적 실패 원인(입력 없는 서버 도구 블록)을 확인한다.

### 2. 대화 기록에 도구 실행 흔적이 없어 모델이 자기 행동을 부정한다 (중요)

- 대화 기록에는 답변 텍스트만 저장된다. 다음 턴의 모델은 "목표를 등록했어요"라는 말만 보고, 그 근거(도구 호출·결과)는 보지 못한다.
- 그래서 4번에서는 검색해서 답한 날씨를 "검색 결과가 아니었으니 믿지 마세요"라고 했다. 9번에서는 실제로 등록한 목표·활동·루틴을 "도구를 호출한 결과가 아니었다"고 정정했다. 데이터는 실제로 다 저장돼 있었다.
- 사용자에게 잘못된 정정을 해서 신뢰를 깎는다.
- 방향: 저장하는 어시스턴트 메시지에 실행한 작업 요약(`action` 이벤트의 summary, 사용한 출처)을 함께 남겨 다음 턴 기록에 넣는다.
- **수정됨:** `messages.actions`(V10)에 실행한 작업을 저장하고, 다음 요청에서 답변 앞에 `[서버 기록]`으로 붙인다. `GET /conversations/{id}/messages`도 `actions`를 내려 준다.

### 3. 프롬프트 캐시를 쓰지 않는다 (비용)

- 모든 호출이 `cache_read_tokens=0`이다. 채팅 요청 한 번의 입력이 약 1.1~1.3만 토큰이다. 도구를 쓴 턴은 요청이 2번이라 약 2.5만 토큰이다.
- 시스템 프롬프트·도구 정의 대부분이 매번 같으므로 캐시를 쓰면 이 부분은 정가의 10%만 낸다. 채팅이 전체 비용의 89%($0.54/$0.60)다.
- 방향: 변하지 않는 앞부분(도구, 고정 지시)에 캐시 지점을 두고, 매번 바뀌는 맥락(시각, 알림, 활동)은 뒤로 보낸다.

### 4. 작은 것

- 통화에서 말한 "하체 운동 1시간"은 기억에는 들어갔지만 활동 기록에는 없다. 통화 중 도구를 쓰지 않았으니 설계대로다. 다음 채팅에서 모델이 "기록에 추가할까요?"라고 먼저 물었다.
- 기동 시 경고: `HV000271: Using @Valid on a container (java.util.List) is deprecated` (`VoiceCallRequest.turns`). `List<@Valid VoiceTurn>`로 바꾸면 된다.
